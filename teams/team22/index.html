Student Placement Predictor

A machine learning model that estimates a student's chance of campus placement from study habits, DSA practice, projects, internships and interview preparation, so students and institutions can see which skills to strengthen.

Problem statement

Placement outcomes are usually judged on a single number such as CGPA, but a student's preparedness has many sides: academics, coding practice, projects, internships, communication and interview readiness. The question we are answering is which of these factors actually separate placed students from not-placed students, and whether a student's profile can be used to predict the outcome.

The final outcome is a classification model that takes a student's profile and returns the probability of being placed, together with the strongest drivers behind that estimate. The trained model is exported to ONNX and runs entirely in the browser, so anyone can try a profile without a server.

Dataset

We used the Student Placement Preparation dataset from Kaggle. It has 1,000 student records and 11 columns, with no missing values. Of these students, 714 were placed and 286 were not placed, so the classes are imbalanced.

The columns are: study_hours_per_day (average daily study time), dsa_hours_per_week and dsa_problems_solved (data structures and algorithms practice), projects_count, internships (0 or 1), cgpa, mock_interviews attended, communication_score, resume_score, hackathons_participated, and the target placement_status (Placed or Not Placed).

Approach

We followed a standard supervised learning workflow, from exploring the data to deploying the final model in a web page.

  • Exploratory analysis: checked class balance, compared CGPA and study hours across the two outcomes, and built a correlation matrix.
  • Feature engineering: created academic_efficiency (CGPA × study hours), practical_experience (projects + 2 × internships) and dsa_overall_score (DSA hours × problems solved ÷ 100), which replaces two highly correlated DSA columns.
  • Model building: split the data 80/20 with stratification, standardised the features, and compared Random Forest with XGBoost. The final model is an XGBoost classifier trained on data balanced with SMOTE (applied to the training split only).
  • Deployment: exported the trained model to ONNX and ran it in the browser with onnxruntime-web, using the same scaler and feature order as in training.

Tools used

Python, pandas, NumPy, matplotlib, seaborn, scikit-learn, imbalanced-learn (SMOTE), XGBoost, ONNX and onnxruntime-web, with HTML, CSS and JavaScript for the web app.
